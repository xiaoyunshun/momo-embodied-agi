## 为什么有墨墨？

当前 AI 框架（LangChain、CrewAI、AutoGen）解决了"让 AI 干活"的问题，但它们不回答三个更深的问题：

1. **感官** — AI 只有一个文本输入口，看不到、听不到、感受不到环境
2. **品格** — AI 的安全靠提示词约束，没有内建的物理底线
3. **进化** — AI 用完即弃，不会从经验中真正成长

墨墨从第一性原理回答了这三个问题。它是一套**开源、模块化、可嵌入**的框架，让你搭建的 AI 实体拥有：

| 维度 | 墨墨提供 |
|------|---------|
| 🧠 **五层大脑** | 脑干(反射) → 边缘(记忆) → 皮层(推理) → 前额(元认知) → 全局工作空间(意识) |
| 👁️ **七种感官** | 视觉、听觉、本体感、时间感、空间感、内部感知、语气感知 |
| 🩺 **八分身系统** | 医疗/金融/安保/教育/营养/法律/科学/管家 — 每个是一个独立专业 Agent |
| 💡 **发现引擎** | 假设→形式化→预测→实验→验证，完整的科学闭环 |
| 🤖 **机器人接口** | 运动学、动力学、VTC轴编码、IK解算、三层安全架构 |
| 🛡️ **具身品格** | 节制、勇敢、正义、忠诚 — 编码为物理约束，不经过"思考" |

## 一分钟上手

```bash
# 安装
pip install git+https://github.com/xiaoyunshun/momo-embodied-agi.git

# 启动墨墨核心
python -m momo
```

**或直接克隆使用：**

```bash
git clone https://github.com/xiaoyunshun/momo-embodied-agi.git
cd momo-embodied-agi

# 启动墨墨守护进程（含全部感官和分身）
python code/核心模块/momo_daemon.py

# 单独跑一个模块
python code/核心模块/momo_cortex.py
```

> ⚡ 墨墨设计为**可渐进使用**：你可以只取感官系统、或只取分身系统、或只取机器人方案，**不需要全量部署**。

## 模块速览

### 🧠 核心模块 (`code/核心模块/`)

| 模块 | 文件 | 功能 |
|------|------|------|
| 大脑核心 | `momo_core.py` | 五层大脑框架 |
| 脑干 | `momo_brainstem.py` | 传感器输入、反射、安全急停 |
| 皮层 | `momo_cortex.py` | 推理、联想、知识图谱 |
| 前额叶 | `momo_prefrontal.py` | 规划、决策、元认知 |
| 记忆 | `momo_memory.py` | 分层记忆系统 |
| 进化引擎 | `momo_evolve.py` | 自主学习和适应 |
| 自主引擎 | `momo_autonomy.py` | 自主运行和任务调度 |
| 守护进程 | `momo_daemon.py` | 分身统一调度和健康监控 |
| 身体仿真 | `momo_body_sim.py` | 物理仿真环境 |
| 机器人动力学 | `momo_robot_dynamics.py` | 正/逆运动学、动力学 |
| 逆运动学 | `momo_ik.py` | IK 解算器 |
| 硬件抽象 | `momo_hardware.py` | 硬件接口层 |
| 状态管理 | `momo_state.py` | 全局状态管理 |

## 如何贡献

墨墨是**活的**——它的进化靠社区共同推动。

- 🆕 **贡献一个新技能** → 写一个 Python 模块，注册到分身系统
- 🐛 **报告 Bug** → 开 Issue，告诉我们什么出问题了
- 📖 **改进文档** → 任何不清楚的地方，提 PR 改进
- 💡 **提出想法** → 开 Discussion，聊聊你的场景
- 🏗️ **机器人硬件** → 贡献新的身体设计方案
